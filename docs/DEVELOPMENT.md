# Gatherline – development notes

Everything that is only relevant for working on Gatherline. The player-facing
description is the [README](../README.md).

## Releasing

One click: go to **Actions → Release → Run workflow**, enter a version like `1.1.0` or
`1.1.0-beta1` and start it. The workflow creates the tag itself. Versions with `beta`
or `alpha` are uploaded as test versions.

Alternatively push a tag yourself:

```bash
git tag v1.1.0
git push origin v1.1.0
```

The GitHub Action builds the zip with the [BigWigs Packager](https://github.com/BigWigsMods/packager)
(`.pkgmeta`: no libraries, nothing to download; `README.md`, `docs/`, `tests/` and
`media/icon-400.png` stay out of the zip; `## Version: @project-version@` is filled in from
the tag; `CHANGELOG.md` becomes the release notes) and attaches it to a GitHub release. It
also uploads to the stores that are set up:

| Store | In `Gatherline.toc` | GitHub secret |
|---|---|---|
| CurseForge | `## X-Curse-Project-ID: …` | `CF_API_KEY` ([API tokens](https://authors.curseforge.com/account/api-tokens)) |
| Wago Addons | `## X-Wago-ID: …` | `WAGO_API_TOKEN` (Wago developer dashboard) |

Secrets go into the GitHub repo under *Settings → Secrets and variables → Actions*.

The CurseForge project description is in [`curseforge.md`](curseforge.md), the project
logo (400×400) in [`../media/icon-400.png`](../media/icon-400.png); both logos are drawn by
[`logo.py`](logo.py). On CurseForge, set GatherMate2 as a *required dependency* and
Shortest Path Forever as an *optional dependency*.

## Files

- `Gatherline.toc` — `GatherlineDB` (settings and routes, account wide). `## OptionalDeps: GatherMate2, ShortestPathForever, GatherPathPlus, GatherPathForever`: the last two only so their saved routes are loaded first, for bringing them over.
- `Locale.lua`, `Locale_deDE.lua` — `ns.L`: `L["English text"]` returns the translation for the game's language, else the key. Keys are whole English texts, format codes in the same order (Lua's `format` has no positional `%1$s`). Theme widgets translate the texts they're given (`Text`, `Card`, `Note`, `Tooltip`, `LabeledSwitch`, `Slider` incl. suffix and zero text, `FlatButton`, `Dropdown` labels, menu labels/subs/groups); everything else calls `L[...]` itself. To check German coverage: collect keys (see git history of this note) and compare with `TRANSLATIONS.deDE`.
- `Theme.lua` — Gatherline's look and widgets. Colours in `C` (jade accent `3fd0a0`), font `Fonts\ARIALN.TTF`. `T.Window(opts)`: header (logo, name, version, close), the menu down the left with group headings (`tab.group`), each page with a title and a short line (`tab.sub`), body below at -44. `FlatButton` (`:SetPrimary(true)` = jade), `T.IconButton(parent, texture, size)`, `T.Upper` (knows ä/ö/ü). `Disabler` calls `:Restyle()` when there is one (buttons); `Swatch:Paint(c)` is a different thing. `T.WINDOW.PAGE_W` 530, `BodyHeight(h)` = h - 48 - 34 - 60.
- `Options.lua` — pages: My routes (rows 92 apart as cards: colour strip at the left (`Swatch`), name, Start (primary), then icon buttons Turn round, Edit, Rebuild, Delete; two info lines; Show), New route, Guidance (Moving on, Stop names, On the map while you ride), Map & lines, No-go areas (`taboo` key internally), About (status of GatherMate2 / Shortest Path / walking map, Bring routes over, credits). `GP.ui` keeps the widgets the tests use.
- `Core.lua` — settings, GatherMate2, routes, drawing, minimap button, `/gl` (`/gatherline`), events, bringing routes over (`GP:ImportSource`, `GP:ImportRoutes(quiet)`: from `GatherPathPlusDB` or `GatherPathForeverDB`, skips same zone + name, copies no-go areas of zones without any, merges the skip list; by itself at `PLAYER_LOGIN` when Gatherline has no routes and `db.imported` isn't set).
- `Sources.lua` (since 1.1.0) — where nodes come from. `GP.Sources.list` = GatherMate2 (`_G.GatherMate2`: `GetNodesForZone`, `DecodeLoc`, `GetNameForNode`, `gmdbs`, messages `GatherMate2NodeAdded/Deleted`) and GatherLite (`LibStub("AceAddon-3.0"):GetAddon("GatherLite", true)`: `GetNodesForMap(type, mapID)` → runtime nodes `{ posX, posY, mapID, object, type }` incl. its predefined database for the kinds it shows, `GetNodeObject(id).name` → `translate("node." .. name)` for the shown name (cached per object id), `IsIgnored(id)` honoured, `On("nodes:added", fn)` for new nodes). GatherLite types herbalism/mining/fishing/containers map to our (GatherMate2) kinds Herb Gathering/Mining/Fishing/Treasure, so saved routes match. `Sources.EachNode` merges: with two sources, a node of the same name within `GP.DUPLICATE_YARDS` (15) of one from an earlier source is skipped (grid buckets). `GP:HasNodeSource()`, `GP:SourceNames()`; `GP:EachNode/Kinds/GatherZones/ListenToGatherMate` go through it.
- `Optimize.lua` — the solver (see below), `Walk.lua` + `Routing/` — walking search, `Navigation.lua` — Start.
- `media/Logo.tga` — 64 x 64, and `media/icon-400.png` (CurseForge), both from `docs/logo.py` (a loop with four nodes and an arrow on a dark rounded square).

## Routes

- `LoadSettings` clears `merge` from routes and `db` (since 1.3.0); their saved `points` are kept, so old routes look the same until Rebuild/Edit.
- A route: `id`, `mapID`, `name`, `kinds` (`{ [GatherMate2 kind] = { [node name] = true } }`), `sight` (yards the loop passes within of each node, 0 = off; missing on 1.0 routes = 0), `nodes` (how many nodes it was made from; `GP:RouteNodes`, falls back to `NodeCount` = stops), `color` `{r,g,b}`, `shown`, `points` (flat `{ x1, y1, x2, y2, ... }`, map positions 0–1 rounded to 4 places, in loop order), `length` (yards). `working` is set while the solver runs (not drawn, not added to).
- Editing (`GP:EditRoute(route, opts)`, since 1.2.0): same checks as `NewRoute` (the name check skips the route itself), sets the new zone, kinds, name and sight, then `Build`s it in a job keeping `id`, `color` and `shown`. If no loop comes out (fewer than 2 stops) every changed field goes back. `opts.mapID` missing = its own zone.
- Skip list (since 1.11.0): `db.skip` = `{ [node name] = true }`, global (every zone, every kind; names, not GatherMate2 ids, since that's what routes keep). `LoadSettings` keeps only string keys set to `true`. `GP:IsSkipped`, `GP:SetSkipped(name, on)` (calls `Changed`), `GP:SkippedNames()` (sorted, for `/gl skipped`). Skipped names are left out by `CollectNodes` (so routes that still list one in `kinds` drop it on Rebuild/Edit; nothing is rebuilt by itself), `AddNode`, `RouteName` (and its "whole kind" count) and `GP:AnyPicked(kinds)`, which `NewRoute`/`EditRoute` and the Make button use instead of "any name in kinds". `ZoneNodes` entries carry `skip`. New route: the node switches take right-clicks (`RegisterForClicks("LeftButtonUp", "RightButtonUp")`): right-click toggles the skip (and unpicks it), a left-click on a skipped one unskips and picks it; skipped ones show off with a grey "(n) - skipped" label; Select all and its Clear all state ignore them. Skipping doesn't touch `route.kinds`, so unskipping and Rebuild brings the nodes back.
- Taboo areas (since 1.12.0): `db.taboos` = `{ [mapID] = { { x1, y1, x2, y2, ... }, ... } }`, map positions 0-1 (rounded to 4 places), at least 3 corners; `LoadSettings` drops anything else. `GP:Taboos(mapID)`, `GP:AddTaboo(mapID, xy)` (turned down under 3 corners, or if `O.SelfCrossing` in yards), `GP:DeleteTaboo(mapID, i)`, `GP:InTaboo(mapID, x, y)`. Both bump `GP.tabooVersion` (the `WallsFor` cache key), call `Changed` and `GP:RebuildZone(mapID)`: every route on that map goes into `GP.queue`; `GP:PumpQueue()` starts the next `RebuildRoute` when no job runs (called from `RunJob` when a job ends). `Build`: `WallsFor(mapID)` (cached `O.Walls` in yards), drops nodes inside one (`route.taboo` = how many; `GP:TabooNote` adds "N nodes in taboo areas left out." to the made/changed/rebuilt chat lines; `route.nodes` counts only the ones used), `O.SetWalls(walls)`, `O.Expand(O.Shortcut(...))`, `O.SetWalls(nil)` (also on a job error). The bends are saved in `route.points` like stops, so drawing, arrows, the line to the route and `RouteLength` need nothing new; `NodeCount` (stops) counts them, `RouteNodes` doesn't. `AddNode`: a node inside an area is ignored; otherwise `BestInsert`/`Place` run with the walls and the `walls:Path` bends of both new legs go in with it. `RemoveNode`: the corners between the two stops that now meet go in.
- Solver walls (Optimize.lua, since 1.12.0): `O.Walls(polys)` (yards, flat lists) puts each polygon anticlockwise, keeps its edges with boxes, and makes the bend points: every corner that sticks out, pushed out along both edge normals by `MARGIN` (3 yards; `O.WALL_MARGIN`), dropped if inside another area; all-pairs shortest ways between them (Floyd-Warshall with `nxt`, `O.Pause` per row). `walls:Inside(p)` (ray casting), `walls:Blocked(a, b)` (box test, then `Crosses` against every edge; touching counts), `walls:Dist(a, b)` (straight if clear, else via `Info(p)`: the corners p sees (`Seen`) and its yards to every corner (`To`), min over the corners b sees; no way at all = 100 x straight; cached per pair, keyed by each point's info, which is remade when a point moves), `walls:Path(a, b)` (the bend points, new tables). `O.SetWalls(w)` makes the module's `Dist` the walled one: the solver (Nearest, Neighbours, 2-opt, Or-opt, shakes), `O.Length`, `BestInsert` and `Place`'s cost all use it; `Euclid` is the straight one, used for grouping radius/reach, `SegDist`, how far a stop moved. With walls, `Group` only groups nodes with a clear line to the first, and falls back to that node if the middle is inside an area or can't see a member; `Place` only takes spots outside the areas with a clear line to the node (`Clear`), else the node itself. `O.Expand(stops)` puts each blocked leg's bends in (`bend = true`). Measured (lua5.1, one block across a 1000 x 1000 field): 200 nodes 0.21 -> 0.52 s, 500 nodes 0.45 -> 1.03 s; with passes within 100 about 2x too.
- World map (since 1.12.0): the pin's `taboo` pool (ARTWORK, under the routes) draws the areas of the map shown (own map only, not on the continent) when `db.tabooShow` (default on, on the Taboo areas tab, not reset by Restore defaults) or while drawing: a red outline (`GP.TABOO_COLOR`, 2 px) and diagonal hatching from `GP.HatchSpans` (lines x + y = c every `GP.HATCH_GAP` 12 screen px, cut against the outline; max 600). Drawing (`GP:StartTaboo(mapID)`, not in combat): `OpenWorldMap(mapID)`, `WorldMapFrame:AddCanvasClickHandler(TabooClick, 100)` (Blizzard_MapCanvas: handlers run on a click, not a drag, with normalized cursor x, y; returning true stops the map's own zoom/navigation, so panning and the scroll wheel still work). Left-click adds a corner, right-click takes one back (with none, it returns false so the map zooms out); clicks on another map pass through. The pin's OnUpdate (our own frame) redraws the `draft` pool: corners, and a line to `map:GetNormalizedCursorPosition()`. `GP.drawBar` (our frame, child of WorldMapFrame, at the top of its ScrollContainer, DIALOG strata): title with the corner count, help (or "Go back to <zone>" on another map, updated from `Provider:OnMapChanged`), Finish (`GP:FinishTaboo`, needs 3 corners) and Cancel (`GP:CancelTaboo`); both remove the handler and reopen the window on the tab (`GP:TabooTabInWindow`).
- Taboo areas tab (Options.lua, `BuildTaboo`, 4th sidebar tab, icon INV_Misc_Bone_Skull_01): zone dropdown (zones with nodes, areas or routes, and yours) and My zone, a note, Draw a taboo area (Keep drawing while one is under way there), Show on the world map, then a scrolling list (rows 30 apart): "Area N - n corners, about W x H yards" (bounding box), Show (opens the map there) and Delete (asks first).
- Names are unique per zone: `GP:RouteNamed(mapID, name, except)` compares trimmed, case-insensitively. `NewRoute` (typed or made-up name) and `RenameRoute` turn a taken name down with a chat line; `RenameRoute` returns false and the row's box goes back to the old name. Before this, a same-named route with the same nodes drew the identical loop under the first one, so it looked missing.
- Yards: `GP:MapYards(mapID)` from `C_Map.GetMapWorldSize`, else the world positions of the map's corners (`C_Map.GetWorldPosFromMapPos`; the world's x runs north, y west). A map the game can't measure is taken as 1500 x 1000 for the solver.
- Work is spread over frames (`GP:RunJob`): one job at a time, ~10 ms a frame (`debugprofilestop`). 600 nodes is about 0.8 s of work outside the game since 1.7.0 (about 4 s before). Each `Step` is meant to be a similar slice of work to before (about 1.5-2 ms outside the game between pauses).
- GatherMate2: `GetNodesForZone(mapID, kind, true)` (coord, nodeID), `DecodeLoc(coord)` (x, y), `GetNameForNode(kind, nodeID)`, `db_types`. Zones with data come from its saved variables behind `gmdbs[kind]` (`__gm2_base_storage` and `__gm2_storage_map`). Messages `GatherMate2NodeAdded` / `GatherMate2NodeDeleted` (zone, kind, coord, name) through `GatherMate2.RegisterMessage(listener, ...)`. All calls are in `pcall`.
- New nodes (`AddNode`, if `db.autoAdd`): into each route on that map with that kind and name, at `O.BestInsert`, unless a stop is already within 5 yards or a leg within `sight` yards; with `sight` the new stop goes at `O.Place` between its neighbours. Deleted nodes (`RemoveNode`) leave routes without sight, if within 1 yard (the others wait for Rebuild).

## Drawing

- World map: a data provider (`WorldMapFrame:AddDataProvider`) with one pin the size of the canvas (`DenormalizeHorizontalSize(1)`), frame level type `PIN_FRAME_LEVEL_MAP_HIGHLIGHT`, ignoring the global pin scale. `Pin:Draw` draws the shown routes of the map shown, and of its child zones on a parent map (`C_Map.GetMapRectOnMap`, lines half as wide). Widths are divided by the canvas zoom so they stay the same on screen; `OnCanvasScaleChanged` redraws.
- Minimap: a frame over `Minimap` with lines, redrawn at most every 0.03 s and only when your position, facing, the zoom (`C_Minimap.GetViewRadius`) or a setting changed. Your position is `C_Map.GetPlayerMapPosition(route.mapID, "player")` (nil off that map: nothing drawn). Pixels per yard = half the minimap's width / view radius. With `rotateMinimap` on, offsets (east, south) turn by `GetPlayerFacing()`: x' = x cos f − y sin f, y' = x sin f + y cos f. Segments are clipped to the circle (`ClipCircle`), or to the square if `GetMinimapShape()` says anything but ROUND (`ClipSquare`).
- Lines come from pools (`LinePool`): a white texture tinted with `SetVertexColor`, `SetThickness`.
- Color and opacity (since 1.5.0), each map on its own: `db.worldAlpha` / `db.minimapAlpha` (percent, 10-100; replaced the shared `db.alpha`, which `LoadSettings` copies into both once and then clears), `db.worldRouteColor` / `db.minimapRouteColor` (default true: each route's `color`), else `db.worldColor` / `db.minimapColor` `{r,g,b}` (default gold). `GP:LineColor(route, "world"|"minimap")` picks the color, `GP:SetLineColor(where, r, g, b)` sets the map's one color. `LoadSettings` copies table defaults fresh and puts a broken color back to the default, clamping each part to 0-1. The minimap's redraw key includes its opacity and color settings.
- Range circle (since 1.7.0, `db.range`, off to start): `GP:DrawRange`, a 64-sided ring of `db.rangeYards` (100, 20-200) round the minimap's middle in its own pool (`mm.ring`), width 2, `db.rangeColor` (default blue `{0.25, 0.80, 1}`) at `db.rangeAlpha` (60%). Clipped like the routes (round or square), so with the minimap zoomed in past it nothing shows. Drawn before the `db.minimap` check, so it stays with the route lines off (and right-click hiding leaves it); redrawn only when its key (view radius, minimap width, its settings, shape) changes. Display tab: a "Range circle" card between Lines (now 214 tall) and More (now at -332, 78 tall, note at -56) to fit the 410 page: switch and color square on top, radius and opacity sliders under.
- Direction arrows (since 1.8.0, `db.arrows` on, `db.arrowsReverse` off; global, not per route): `GP.ArrowMarks(xs, ys, n, spacing, reverse)` walks the loop from stop 1 (reversed: 1, n, n-1, ... 2) and puts a mark every `spacing` pixels of the way round, the first at half a spacing, so the spacing is even across short and long legs and the marks stay put on the route as you move; capped at 2000; none for fewer than 3 stops. `DrawArrow` makes a ">" of two lines from the tip (half the size ahead of the mark) to wings a size behind and 0.6 x size to each side, in the line's color, opacity and width. Own pools (`pin.arrows`, `mm.arrows`) so the route line pools still hold one line per leg. Gaps `GP.ARROW_GAP` (screen pixels): world map 80 (divided by the canvas zoom like the width), minimap 40. Sizes: world `max(8 / scale, width * 3)`, minimap `max(7, minimapWidth * 3)`. On the minimap only arrows whose mark is `size` inside the edge are drawn (circle or square); its redraw key includes both settings, and turning the minimap lines off clears its arrows. Display tab: a card at -224 under Lines with Show arrows and Reverse direction (dimmed while arrows are off); called "Direction arrows" (60 tall) in 1.8.0, "Following a route" (90 tall, with Line to the route at -60) since 1.9.0. Range circle at -324 and More at -432 (page ends at 510 of 530). Since 1.10.0 the gaps between cards are 6 instead of 10 (Following a route at -220, Range circle at -316, More at -420, ending at 498) to fit Restore defaults (150 x 22) at -506, bottom left, ending at 528 of 530.
- Line to the route (since 1.9.0, `db.joinLine`, on): in `DrawMinimap`, `GP.NearestOnLoop(sx, sy, n, 0, 0)` (closest point on any leg; 2 stops = one leg) for every route drawn, and the nearest of all gets `DrawJoin`: dashes `JOIN_DASH` 6 on, `JOIN_GAP` 4 off, from the middle toward it, stopping at the point or the minimap's edge (`inside`, or the square's edge in that direction), in that route's minimap color and opacity, `minimapWidth - 1` wide (at least 1). None within `JOIN_MIN` (20 yards). Own pool `mm.join`; the redraw key includes the setting; cleared with the minimap lines.
- Lap time (since 1.9.0): `GP:LapTime(route)` = length / `GP:Speed()` in words ("under a minute", "about N min", "about H h MM min"). `Speed()` is `db.speed` (yards/s) or `FOOT_SPEED` 7. `GP:SampleSpeed()` runs from the minimap frame's OnUpdate about every 2 s (60 ticks of 0.03): `GetUnitSpeed("player")`'s run speed, skipped if `issecretvalue` says it's hidden (Forever marks GetUnitSpeed `SecretWhenUnitStatsRestricted`), not a number, at most 7.5 (on foot) or over 100; rounded to 0.1 and kept in `db.speed`; all in `pcall`. When it changes with the window open, the window refreshes. The Routes row's second line is now "About N min a lap[ on foot][  -  passes within N yards]" (" on foot" while `db.speed` is unset).
- Restore defaults (since 1.10.0): the Display tab's bottom button (`GP.ui.restoreDefaults`) asks with `GP:Confirm`, then `GP:RestoreDefaults()` sets every key in `GP.DISPLAY_KEYS` (Core.lua, next to `GP.DEFAULTS`) back to `GP.DEFAULTS` (color tables copied, so later changes never touch the defaults), clears `db.hiddenWas`, calls `UpdateMinimapButton` and `Changed`. Not reset: routes, `minimapAngle`, `sight` (New route's slider), `nextColor`, `speed`. A test fails if a new `GP.DEFAULTS` key is neither in `DISPLAY_KEYS` nor in its `notOnTab` list, so add new Display settings to `DISPLAY_KEYS`.
- Right-click on the minimap button (`ToggleLines`) turns both kinds of line off and remembers which were on (`db.hiddenWas`).

- 1.2.0 bug (fixed 1.2.1): `r.rebuild` (a plain `FlatButton`) never had `T.Disabler`, so `r.rebuild:SetDisabled` in the Routes refresher was a nil call as soon as a zone had a route. `GP:RefreshConfig` runs the refreshers in order, so the error stopped everything after it: New route's zone menu kept `keys = {}` (clicking it did nothing), its label and note stayed empty and the sliders never got their `Refresh`. Since 1.0.0; it only showed once a route existed. The test stub hid it because any unknown method on a fake frame was a no-op; now the methods the addon adds itself (`ADDON_METHODS` in `tests/wowstub.lua`: `SetDisabled`, `SetOn`, `IsOn`, `SetHover`, `Paint`, `Refresh`, `Choose`, `SetContent`) read nil unless added, as in the game. Add to that list when Theme.lua or Options.lua grows another such method.

## Gatherline (fork)

- Renamed throughout (`Gatherline`, `/gl`, `GatherlineDB`, `GatherlinePinTemplate`) so it loads beside GatherPath Forever. `## OptionalDeps: GatherMate2, ShortestPathForever`.
- `Navigation.lua` (Baustein 1): `GP:StartNav(route, laps)`, `GP:StopNav(quiet)`, `GP:IsNavigating(route?)`, `GP:NavStatus()`, `GP:NavCandidate()`. Positions p = 1, 2, ... along the loop from the joining stop in the arrows' direction (`db.arrowsReverse`), `last` = laps * n + 1 or huge (`db.navLaps`, 0 = endless). `Send(p)` hands `NAV_AHEAD` (10) stops to `ShortestPathForever.API.NavigateRoute` as owner `Gatherline`; a 0.5 s ticker (plus `Subscribe`, deferred a frame) reads `CurrentStop`: heading for the last stop handed over -> `Send(p)` again; within `NAV_CATCH` (40) yards of one of the next `NAV_CATCH_AHEAD` (6) stops -> `Send(q + 1)`; `Ended` "arrived" -> next batch or finish; "cleared"/"replaced"/"cancelled" -> stop. Refused (combat, Journeys off) -> `pending`, retried, given up after `NAV_GIVE_UP` s outside combat.
